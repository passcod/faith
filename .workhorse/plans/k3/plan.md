# Support the QUERY method in NAPI

## What we found

QUERY already round-trips mechanically. Faith's method handling is generic: any HTTP
token passes through `Method::from_bytes` unchanged (`crates/web-faith/src/request/send.rs:56-62`),
QUERY is not in the fetch-normalised set so it is sent as given (already upper case, matching
the fetch standard), and there is no body-on-method guard beyond GET/HEAD, so a body flows.
The GET/HEAD "no body" throw (spec REQ, `fetch/request.md` Body section) does not touch QUERY.

QUERY is not just another custom method, though. Per draft-ietf-httpbis-safe-method-w-body
it is **safe, idempotent, and cacheable**, carries a request body, and requires a `Content-Type`.
That gives it semantics Faith does not currently extend to it.

## Scope for this card

1. **Documentation.** `method?: string` in `index.d.ts:1243` has no doc comment at all, and
   nothing on the NAPI/TS surface states which methods are supported or that arbitrary methods
   pass through. Document the method option, including that QUERY (and any token method) is
   supported. The `.d.ts` is generated by napi, so the doc lives on the Rust field in
   `crates/web-faith-napi/src/options.rs` (the `method` field, near line 160).

2. **Retry idempotency.** `is_idempotent` (`crates/web-faith/src/retry.rs:53-58`) is an
   allowlist: `GET, HEAD, OPTIONS, TRACE, PUT, DELETE`. QUERY falls through to "not retried",
   even though the draft says it may be retried after a connection failure. Add QUERY.
   - **Wrinkle:** `http` 1.4.0 has no `Method::QUERY` constant (confirmed). QUERY is an
     extension method, so the `matches!(*method, Method::GET | ...)` arm cannot gain a
     `Method::QUERY` — the fix is a string comparison, e.g. `|| method.as_str() == "QUERY"`.
   - Spec to update: POOL (`.workhorse/specs/agent/connection-pool.md:34`) lists the
     retryable methods. Add QUERY to that sentence so spec and code stay in step.

3. **Round-trip test.** Add a test asserting a QUERY request round-trips with a body (the
   existing `test/http-methods.test.js` `methodEcho` harness fits; assert the method reaches
   the origin as `QUERY`). Consider a case asserting a QUERY that dies before a response is
   retried, alongside the existing retry tests.

## Deliberately out of scope

**Caching QUERY** — split to card **N3** ("Cache QUERY responses with a body-aware cache key").
QUERY is cacheable but its cache key must incorporate the request body; Faith's cache keys on
method + URI only (`http-cache-reqwest`). Larger, separable piece.
